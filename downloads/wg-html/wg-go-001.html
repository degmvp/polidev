001 | Network & Port Monitor

Monitoramento e diagnóstico de conectividade TCP e HTTP/HTTPS

Documentação técnica da ferramenta 001

Voltar para WG-TOOLS

1. Visão geral

O Network & Port Monitor é um utilitário de linha de comando desenvolvido em Go para verificar a conectividade com serviços de rede e endpoints web. Apresenta o resultado da tentativa de conexão, o tempo de resposta e informações de diagnóstico.

2. Recursos

  • Teste de conectividade TCP em host e porta.
  • Verificação de endpoints HTTP/HTTPS e retorno de status HTTP.
  • Medição de latência em milissegundos.
  • Registro de resultados em formatos JSON e CSV.
  • Compilação nativa para Windows e Linux.

3. Arquivos e plataformas

Fonte Go: wg-go-001-network-port-monitor.go

Executável Windows: wg-go-001.exe

Executável Linux: wg-go-001-linux

Diretório de fontes no Windows: E:\wggo\

Os fontes são mantidos fora dos diretórios públicos de downloads.

4. Compilação no Windows

cd E:\wggo
go build -o wg-go-001.exe .\wg-go-001-network-port-monitor.go

Para gerar a versão Linux a partir do Windows, em PowerShell:

$env:GOOS = "linux"
$env:GOARCH = "amd64"
go build -o wg-go-001-linux .\wg-go-001-network-port-monitor.go

Após a compilação cruzada, restaure as variáveis de ambiente, se necessário, antes de compilar novamente para Windows.

5. Execução e testes

A ferramenta recebe destinos TCP e URLs HTTP/HTTPS conforme os parâmetros implementados no programa. Na execução em PowerShell, ao informar uma lista vazia de URLs, utilize a forma -urls= para evitar a interpretação de um argumento vazio.

Exemplos de destinos de teste:

  • TCP: www.google.com:443
  • HTTP/HTTPS: https://www.google.com
  • Ambiente local: localhost:3000 ou localhost:1433, quando houver serviço correspondente.

Os nomes completos dos demais parâmetros devem ser consultados no programa ou na saída de ajuda da versão compilada; não são presumidos nesta documentação.

6. Interpretação dos resultados

OK: conexão ou requisição concluída com sucesso. Falha: serviço indisponível, conexão recusada, timeout ou outro erro informado no detalhe.

O tempo de resposta é apresentado em milissegundos. O resultado HTTP inclui o código e a descrição do status quando disponíveis.

[
  {
    "target": "www.google.com:443",
    "kind": "TCP",
    "status": "OK",
    "latency_ms": 102,
    "detail": "conexao estabelecida"
  },
  {
    "target": "https://www.google.com",
    "kind": "HTTP",
    "status": "OK",
    "latency_ms": 713,
    "detail": "200 OK"
  }
]

Exemplo abreviado de uma execução anterior; latências e resultados variam conforme a rede.

7. Relatórios

Os resultados podem ser gerados em JSON e CSV para análise, registro e comparação. Os campos observados incluem data/hora, destino, tipo do teste, status, latência e detalhe.

8. Observações operacionais

  • Uma porta fechada ou sem serviço pode retornar conexão recusada; isso não significa defeito no monitor.
  • Resultados dependem da conectividade, DNS, firewall e disponibilidade do destino.
  • O executável Linux deve ser testado na VM Ubuntu antes da homologação nessa plataforma.
