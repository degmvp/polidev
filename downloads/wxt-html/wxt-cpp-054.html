T-SQL Regex Modernizer

Analisador estático de código T-SQL para identificar oportunidades de modernização com expressões regulares do SQL Server 2025.

Versão 1.0 · Windows · Offline · Sem ODBC · Somente leitura

← Voltar para WX-TOOLS

Visão geral

A ferramenta examina arquivos .sql e diretórios, localiza padrões conhecidos e apresenta recomendações para revisão humana. Não conecta ao banco, não executa SQL e não altera os arquivos analisados.

Regras disponíveis

RegraDetecçãoOrientação
R1PATINDEX(...)Avaliar REGEXP_INSTR após validação do padrão; não converter diretamente curingas LIKE.
R2Casos específicos de LIKE e NOT LIKE com classes de caracteresSugerir REGEXP_LIKE, preservando identificadores qualificados e delimitados; evitar proposta quando houver cláusula ESCAPE detectada.
R3REPLACE(REPLACE(...))Avaliar REGEXP_REPLACE preservando ordem e semântica.
R6CHARINDEX('%', ...)Alertar que % é literal em CHARINDEX.

As regras R4 e R5 não estão implementadas nesta versão.

Comandos

ComandoFunção
scanLista as ocorrências identificadas.
suggestMostra propostas e notas de revisão.
dry-runExibe ANTES e DEPOIS (proposta não aplicada).
reportExibe ou grava relatório textual em Markdown.
selftestExecuta verificações internas.

Exemplos de execução no PowerShell

& "E:\@LIB-C++\bin\wxt-cpp-054-t-sql-regex-modernize.exe" selftest
& "E:\@LIB-C++\bin\wxt-cpp-054-t-sql-regex-modernize.exe" scan "C:\SQL\consulta.sql"
& "E:\@LIB-C++\bin\wxt-cpp-054-t-sql-regex-modernize.exe" suggest "C:\SQL\consulta.sql"
& "E:\@LIB-C++\bin\wxt-cpp-054-t-sql-regex-modernize.exe" dry-run "C:\SQL\consulta.sql"
& "E:\@LIB-C++\bin\wxt-cpp-054-t-sql-regex-modernize.exe" report "C:\SQL" -r "--out=C:\SQL\relatorio.md"

O parâmetro -r inclui subdiretórios. O parâmetro --out=... é destinado ao comando report.

Exemplo de sugestão

SQL original:
SELECT * FROM dbo.Clientes WHERE [Nome] LIKE '%[0-9]%';

Sugestão para revisão:
REGEXP_LIKE([Nome], '[0-9]')

Atenção: a sugestão não é aplicada automaticamente. Validar collation, tratamento de NULL, compatibilidade e equivalência semântica antes de usar no SQL Server 2025.

Validação e limitações

  • Compilação no Visual Studio e bateria de 50 testes conduzida no ambiente Windows do projeto.
  • Suporte testado para comentários, strings SQL, identificadores delimitados, arquivos e diretórios.
  • Arquivos UTF-16 com BOM são rejeitados com mensagem específica; suporte UTF-16 não implementado.
  • O analisador é heurístico: não substitui parser completo de T-SQL nem validação de execução em banco.
  • Não há garantia de equivalência automática entre padrões LIKE/PATINDEX e expressões regulares.
