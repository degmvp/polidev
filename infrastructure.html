Infrastructure

The operational environment supporting the POLYDEV ecosystem: Windows 11, Hyper-V, Ubuntu Linux, networking, PostgreSQL administration, Supabase access, backups and infrastructure recovery.

“Reliable infrastructure is not the environment with the greatest number of components. It is the environment that can be understood, maintained and rebuilt.”
Author: Degmar Barbosa Version: 1.0 Date: 2026-07-27 Status: Living Document
Chapter 00

Infrastructure Overview

POLYDEV uses a hybrid development environment combining a Windows workstation, Linux virtualization, GitHub Pages and a managed PostgreSQL database.

The infrastructure was built to support development, database administration, testing, publication, backup and future automation without requiring a complex local data center.

W11

Windows Host

Primary workstation, development interface, DBeaver, GitHub workflow and Hyper-V administration.

LIN

Ubuntu Linux

Virtual machine dedicated to command-line operations, PostgreSQL tools, scripts and Linux administration.

PG

Managed PostgreSQL

Supabase provides the production data layer used by the public POLYDEV application.

Infrastructure objective

The environment must remain understandable enough that it can be reconstructed from documentation, backups and verified configuration records.

Chapter 02

Hyper-V Environment

Hyper-V provides the virtualization layer used to run the POLYDEV Ubuntu environment.

Virtual Machine

The operational Ubuntu virtual machine is identified as VMHYP.

Virtual Switch

The external virtual switch is identified as rede externa.

PowerShell 
Get-VMSwitch

Get-VMNetworkAdapter -VMName VMHYP

Connect-VMNetworkAdapter `
  -VMName "VMHYP" `
  -SwitchName "rede externa"
Hyper-V validation

When the Ubuntu VM loses network access, verify the VM network adapter and its connection to the external switch before changing Linux or database settings.

Chapter 05

Shared File Environment

Windows and Ubuntu share operational files through the active network share named compartilhado.

The share allows files to move between the Windows development environment and the Ubuntu administration environment without recreating content manually.

Windows access

The share is accessed through the VM network address using the SMB path.

Ubuntu access

The shared location is accessible from the Linux file manager and command line.

Verified operation

File creation, copying and deletion were successfully tested in both directions.

Active share rule

The operational shared location is compartilhado. An older path named D:\VM-SHARE does not represent the active synchronization point.

Chapter 10

Backup Strategy

POLYDEV recovery depends on independent protection of code, content, database and operational knowledge.

01
Source Code

Git and GitHub repository.

02
Content Files

Repository and local copies.

03
Database

PostgreSQL logical dump.

04
Configuration

Protected operational records.

05
Documentation

POLYDEV Master Guide.

pg_dump Pattern 
pg_dump \
  --host="$PGHOST" \
  --port="$PGPORT" \
  --username="$PGUSER" \
  --dbname="$PGDATABASE" \
  --format=custom \
  --file="polydev_$(date +%Y-%m-%d).backup"
pg_restore Pattern 
pg_restore \
  --host="$PGHOST" \
  --port="$PGPORT" \
  --username="$PGUSER" \
  --dbname="$PGDATABASE" \
  --clean \
  --if-exists \
  "polydev_backup_file.backup"
Backup validation

A backup is not complete until the file exists, its size is reasonable, the execution log is reviewed and a restore procedure is documented.

Chapter 11

Infrastructure Security

Protect database credentials

Store passwords outside public source code and public documentation.

Separate public and administrative keys

Browser applications may use public anonymous keys. Administrative keys remain private.

Restrict remote access

SSH and shared folders must be available only where operationally required.

Preserve operating system updates

Windows, Ubuntu and database tools must receive controlled security updates.

Keep multiple backup copies

Critical database and source backups must not depend on a single disk or machine.

Document configuration changes

Network, Hyper-V, database and security changes must remain reproducible.
